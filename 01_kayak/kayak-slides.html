The problem

Kayak wants to recommend where to go, with no data yet

“70% of their users who are planning a trip would like to have more information about the destination they are going to.”Project brief, Kayak marketing team · scope: 35 French cities, real weather and hotel data

What the brief asks, step by step

  • “Scrape data from destinations”
  • “Get weather data from each destination”
  • “Get hotels' info about each destination”
  • “Store all the information above in a data lake”
  • “Extract, transform and load cleaned data from your datalake to a data warehouse”

The three deliverables

  • A .csv file in an S3 bucket with weather and hotels for each city
  • A SQL database with the same cleaned data
  • Two maps: Top-5 destinations, Top-20 hotels

Two sources, two ways to collect

Weather · OpenWeather API

  • Geocoding endpoint: city name → latitude, longitude
  • Forecast endpoint: 5 days, one value every 3 hours
  • One HTTP request per city with requests, JSON answer
  • Each city gets a city_id, to link every hotel to its city's weather

Hotels · Booking.com scraping

  • No API. Pages are built in JavaScript → Selenium drives Chrome
  • BeautifulSoup reads the page. CSS classes first, but Booking regenerates them; then the stable data-testid attributes: property-card, title, review-score
  • One visit per hotel for coordinates and the real description
  • Checkpoint after each hotel, stop at the first CAPTCHA

Limits & choices

What I chose, and what it costs

Choices I defend

  • OpenWeather for geocoding, not Nominatim: coordinates and weather from the same provider
  • Supabase instead of AWS: same S3 API, same boto3 code, account issue only
  • Simple score: three terms anyone can read, no weighting to defend

Known limits

  • 5-day forecast, not 7: the free API tier
  • 34 cities of 35: Gorges du Verdon is a natural site, no coordinates returned
  • Top-20 ranks on Booking score only, reviews not counted: in the file, a 9.7 with 28 reviews ranks above a 9.6 with 486
  • Scraping depends on Booking's page markup: a redesign breaks the collector
