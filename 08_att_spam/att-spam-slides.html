The problem

AT&T flagged spam by hand. Now it wants it automatic.

“One of the main pain point that AT&T users are facing is constant exposure to SPAM messages. AT&T has been able to manually flag spam messages for a time, but they are looking for an automated way of detecting spams.”Project brief, AT&T

The goal

  • Build a spam detector from the content of the message only
  • With a deep learning model
  • The real question: will the score hold on messages never seen?

The deliverables

  • A notebook that cleans the text and trains a model
  • State the achieved performance clearly
The brief's two hints, followed: “Start simple” → Model 1 · “Transfer learning” → Model 3, pre-trained word vectors, and Model 4, a whole pre-trained language model.

How I made it usable

  • Three unnamed columns: the ends of messages cut by a comma. Glued back to the text
  • Text cleaned, then duplicates removed: 476 of them
  • Split 70 / 15 / 15: learn, validate, test
The trap. Always answering “legit” scores 88 % accuracy and catches zero spam. So I follow precision (of the flagged messages, how many are really spam) and recall (of the real spams, how many are caught).

Why three sets, not two. The validation set picks the model and its decision threshold. If the test had been used for that, its score would be flattering. The test is read once, at the end, on the chosen model only.
What the networks share. Each message becomes a sequence of word vectors: numbers that place similar words close to each other. M1 averages them; M2 and M3 read them in both directions. The transfer: M3 reuses vectors learned on a large English corpus, kept frozen; M4 reuses a whole pre-trained language model, DistilBERT, adapted to our SMS.

Limits & choices

A clean score, on a small number of spams

Known limits

  • 90 spams in the test: one message moves F1 by about one point, so the ranking of models is fragile
  • One split only: cross-validation would give steadier numbers
  • DistilBERT is heavy: 66 million parameters, 1,000 times the trained weights of M3. M3 is the light fallback, and the model saved
  • Spam evolves: not tested on recent messages

Choices I defend

  • Start simple, as the brief advises: M1 averages word vectors
  • Duplicates removed after cleaning: before that fix, 11 test spams were already in the training set, a data leak
  • Model and threshold chosen on validation only; threshold 0.35 for DistilBERT
  • Keras networks stopped when the validation loss stops improving; DistilBERT trained 2 passes only
Validation 96.1 %, test 95.6 %: the score holds on messages never used for a decision. Each set holds only about 90 spams, so the test figure is the one to state.

Takeaways
Conclusion

A first filter, measured properly

  • It works: 19 spams in 20 caught, 4 false alarms in 675 real messages
  • The figure is reliable: measured on messages the model had never seen
  • Ready as a first filter. One setting to decide with AT&T: stricter, to block more spam, or more cautious, to never block a real message
  • Next: check the model on recent SMS, because spam changes
